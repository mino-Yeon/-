🔍 <a> vs <button> — 언제 무엇을 써야 할까?

생긴 게 같아도 목적이 다르면 태그도 달라야 합니다. 4가지 케이스를 잘못된 예 vs 올바른 예로 비교합니다.

🔗
<a> 를 쓰는 기준 클릭 후 URL이 바뀌거나 페이지가 이동하는가?
→ 그렇다면 <a href="...">
🖱
<button> 을 쓰는 기준 클릭 후 페이지 안에서 무언가 동작하는가?
→ 그렇다면 <button>

케이스 1 — 다른 페이지로 이동하는 경우

버튼처럼 생겼어도 클릭 후 URL이 바뀐다면 → <a>

❌ 잘못된 예
<button> 시작하기 </button> /* 이동이 목적인데 button을 사용 */
button은 이동 기능이 없습니다. 우클릭 새 탭 열기 불가, 검색엔진이 링크로 인식하지 못합니다.
✅ 올바른 예
<a href="/start"> 시작하기 </a> /* 이동이 목적 → a + href 사용 */
href 덕분에 우클릭 새 탭 열기 가능, 검색엔진이 링크로 인식, 스크린리더가 "링크"로 올바르게 읽습니다.

케이스 2 — 페이지 안에서 동작하는 경우

링크처럼 생겼어도 클릭해도 URL이 바뀌지 않는다면 → <button>

❌ 잘못된 예
<a href="#"> 최신순 정렬 </a> /* 동작이 목적인데 a href="#" 사용 */
href="#" 는 클릭 시 스크롤을 맨 위로 올리는 부작용이 있습니다. 이동 없는 동작에 <a>는 부적절합니다.
✅ 올바른 예
<button> 최신순 정렬 </button> /* 동작이 목적 → button 사용 */
href 부작용 없음. 스크린리더가 "버튼"으로 올바르게 읽고, 키보드 Enter / Space 모두 작동합니다.

케이스 3 — 폼 제출 버튼

폼을 제출하는 버튼은 → <button type="submit">

❌ 잘못된 예
<form> <input type="text"> <a href="#"> 제출하기 </a> </form> /* a 태그로 폼 제출 시도 */
<a>는 form과 연결되지 않아 Enter 키 제출 불가, required 등 브라우저 유효성 검사가 동작하지 않습니다.
✅ 올바른 예
<form> <input type="text"> <button type="submit"> 제출하기 </button> </form> /* button type="submit" 사용 */
Enter 키로 제출 가능, required·pattern 등 브라우저 유효성 검사 자동 동작, 스크린리더가 "제출 버튼"으로 읽습니다.

케이스 4 — 드롭다운 메뉴 열기

드롭다운이란 버튼을 클릭하면 아래로 메뉴가 펼쳐지는 UI입니다. 메뉴를 여는 버튼과 메뉴 안의 항목은 목적이 달라 태그도 달라집니다.

▶ 드롭다운 동작 미리보기 (버튼을 클릭해보세요)
  • 프로필
  • 설정
  • 로그아웃

👆 "내 계정 ▾" 버튼 → 페이지 이동 없이 메뉴가 펼쳐짐 → button 사용
"프로필", "설정" 항목 → 클릭하면 해당 페이지로 이동 → a 사용

❌ 잘못된 예
<!-- 열기 버튼도 a 사용 --> <a href="#">내 계정 ▾</a> <ul> <li><a href="#">프로필</a></li> <li><a href="#">설정</a></li> </ul>
열기 버튼은 이동이 없는 동작인데 a href="#" 사용 → 스크롤 맨 위로 이동하는 부작용, 스크린리더 혼란
✅ 올바른 예
<!-- 열기: 동작 목적 → button --> <button>내 계정 ▾</button> <ul> <!-- 항목: 이동 목적 → a --> <li> <a href="/profile">프로필</a> </li> <li> <a href="/settings">설정</a> </li> </ul>
같은 컴포넌트 안에서도 목적에 따라 태그가 달라집니다 — 열기(동작) → button / 항목(이동) → a
